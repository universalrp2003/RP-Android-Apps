# Voice Mail feasibility lab — private test only

This debug experiment does **not** answer calls, play a greeting, record voicemail, or demonstrate that a normal APK can implement iPhone Live Voicemail. It is isolated from the existing apps and has a separate application ID. It requests RECORD_AUDIO only after a button press. It has no network, call state, call answering, contacts, accessibility or storage permissions; no audio is saved, uploaded or logged. Samples are analysed in memory only, for up to five seconds, and the test stops on backgrounding. Android can refuse the source, return silence, or supply unexpected audio. A nonzero level is not proof that it contains the caller's voice. No privacy, compatibility or telephony capability is guaranteed by this test.

Test only a disposable, non-emergency call with everyone informed and consenting. Start a normal call manually with another device. Open the lab while the call remains active, and explicitly initiate the caller audio test. Never share audio, phone numbers, caller identity or call screenshots. You may share only the displayed numerical result or error. Compare caller-silent and caller-speaking tests, but even different levels cannot conclusively establish voice identity. Stop immediately if unexpected behavior occurs.

Modern Android generally reserves VOICE_DOWNLINK capture for privileged system apps; denial is an expected, useful result. This experiment does not request or claim privileged permissions, try accessibility bypasses, root, ADB grants, or hidden APIs. It is not published, not part of the application catalog, and must not be relied on to take messages.
