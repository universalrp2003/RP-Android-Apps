# Oor1.1.18 candidate — locality, GNSS, spacing and restart review

Private owner screenshots received6 November2026 are reference-only and are not copied into this repository or website. No publication is authorized for this candidate. Public1.1.17 and all other app releases stay unchanged.

## Findings and changes

- Confirmed code issue: reverse geocoding used `Address.subAdminArea` as a missing-locality fallback. Administrative areas must not become announced towns. Removed that fallback; reject explicit district/taluk/tehsil labels and district-equivalent localities, prefer a valid finer sublocality for local announcements only when the same-city/subarea setting permits it. Family sharing has a separate locality-only field and never inherits the finer sublocality. Provider locality may itself be coarse/wrong; this is not independent boundary/ground-truth validation. Ambiguous district-headquarters localities can now be suppressed rather than falsely promoted. No new remote place provider, tracking, identifiers or uploads.
- GNSS diagnostics use an explicit opt-in dialog with its own bounded scroll and persistent close control; no expanding block displaces home history. Subscribe only when opened, RESUMED, tracking is user-enabled, GPS enabled and existing precise-location permission already granted. Unregister on hide/background/stop/permission change/disposal; no extra location request or permission prompt. Show receiver-reported/used-in-fix counts, constellation and up to24 signal-detail rows. Snapshot expires after10seconds; callback processing throttled to2seconds, at most256 samples. Not reported/stale is not zero. Counts cannot prove which satellites produced a fused location/destination distance; explanation is visible. No satellite records are persisted or uploaded.
- Compact family summary aligns the latest report and switch, removes repeated own-sharing label, reduces padding/gaps, retains real upload/waiting/stop-pending states and the global details/controls button. Do not shrink switch touch targets. History suppresses exact duplicate title/spoken text while retaining richer announcements and outcomes. Remove redundant navigation-bar inset, reduce outer/card gaps. Native bilingual UI checks cover100% and200% font sizes; no owner screenshots in test artifacts.
- Definite lifecycle issue found: the per-service speech executor was not shut down in `onDestroy`. Shut it down and invalidate readiness; cap running+queued online speech to6, honestly log excess/rejected requests as skipped. Existing accepted voice engines/retry/playback policies are not rewritten. This is defensive cleanup, not proof of a reboot cause.
- Destination milestones ignore fixes without finite coordinates, measured accuracy<=65m and monotonic age<=30s. The existing one-shot distance/arrival mask remains. Add15second coroutine timeout for asynchronous reverse geocoding; legacy synchronous platform geocoding on IO may not be interrupted immediately by cancellation.
- Local Android30+ last app-exit category uses own-package ApplicationExitInfo only. No stack traces, owner locations, arbitrary descriptions or telemetry collected. An app-exit category is not a whole-device reboot diagnosis; it may describe an older exit. Unsupported/absent report is shown as unavailable.
