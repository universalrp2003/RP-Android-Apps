# Animal communication: research and prototype decisions

Scope: evidence review for an experimental Android app, not a claim to have surveyed all work worldwide. Source observations are not proof that a model works on the owner's device, in Tamil Nadu, for a particular animal, or across noise, dialects and individual variation.

## What science can and cannot do

1. [NatureLM-audio research paper](https://arxiv.org/html/2411.07186v2) evaluates diverse bioacoustic recognition and free-text tasks; performance varies dramatically between datasets and labels. It does not establish translations or validated replies. Its [model card](https://huggingface.co/EarthSpeciesProject/NatureLM-audio) describes CC-BY-NC-SA model weights, an 8B language model backbone, and out-of-scope tasks. Code, model, datasets and base model may carry different terms. Not bundled; size, inference requirements, rights, audio privacy and hallucination risk need investigation before any optional integration.
2. [ZF-AIM zebra finch study](https://www.biorxiv.org/content/10.64898/2026.02.12.705387v3) describes species-specific experimental real-time generated call interactions in a controlled research setting. It does not show language translation, safety, generalization to pets/crows/cows/lizards, or a phone-ready reply generator. The methods and animal-welfare oversight are not interchangeable with casual outdoor playback.
3. [BirdNET Analyzer](https://github.com/birdnet-team/BirdNET-Analyzer) classifies bird vocalizations; review the exact model/version and permitted use separately from code licensing. The archived [BirdNET-Lite](https://github.com/birdnet-team/BirdNET-Lite) 6K model is CC BY-NC-SA 4.0. We added a separate, optional non-commercial interface to that exact model, which the user imports manually; it is not bundled. The old model is deprecated upstream and not asserted to be the latest or most accurate BirdNET release. It requires 3 seconds of 48 kHz input, 6,362 labels, and no-location metadata; our output gate is uncalibrated, so species guesses are not meaning or individual identity. Real-world and target-phone testing is still needed. Location is not collected, potentially reducing precision. Labels and licence are included, with attribution to Cornell Lab of Ornithology and BirdNET.
4. [Google YAMNet](https://github.com/tensorflow/models/tree/master/research/audioset/yamnet) predicts 521 general AudioSet events. The included Lite version is offline and relatively small. It includes broad dog, cat, cattle, crow, bird, rodent, insect and frog classes, but no dedicated gecko category and no intent classifier. The prototype's 0.25 animal score and 0.45 competing sound gate are uncalibrated conservative UI heuristics, not accuracy claims. The strongest qualifying result from three separately scored windows is shown; multiple related guesses can refer to the same sound. Broad ancestor classes are no longer counted as competitors to a selected subclass (e.g. Bird vs Crow), but this heuristic is not validated and may increase false positives. The model may be wrong or miss quiet/distant sounds.
5. [Rat ultrasonic study](https://pubmed.ncbi.nlm.nih.gov/27746726/) reports different rat call families, including high ultrasonic vocalizations with context-dependent roles. A 16 kHz capture pipeline cannot represent a 22–50 kHz ultrasonic signal. Ordinary phones' microphones and speakers cannot be assumed to handle that range. A capable external ultrasonic microphone/speaker and a validated species-specific model would need a separate design, safety, permission and hardware tests.
6. [Gecko sound research](https://doi.org/10.1093/iob/obz014) shows vocal variation among geckos; many lizards use other modalities. A generic bird chirp result is not evidence of a gecko or its intent. Ants rely heavily on chemicals and touch; a phone mic is not a pheromone sensor.
7. [Ethical playback guidance](https://rochesterbirding.org/conservation/ethical-birding/birdsong/) explains that recorded calls can change behavior and restrictions differ by place. No automatic playback, loops, loudness changes, claims of positive meanings, or near-nest encouragement. Manual sample replay is explicitly labelled not a reply and warns about wildlife and human voices. This is not a blanket claim that a playback is safe.

## Next steps before any claims or release

- Test on labelled, consented, appropriately licensed animal recordings representative of South Indian environments, held-out species, distance, traffic, wind and overlapping speech; report false positives/negatives and unknown rates rather than only examples. Do not commit personal audio.
- Confirm actual microphone and speaker capability on target phones, screen-off/interruptions, permission denial, lifecycle cancellation, CPU, battery, memory and headphones; no background recording.
- For a species-specific reply, obtain an independently validated model, approved licence and provenance, species/context data, an animal welfare review and measured playback hardware. Showing an acoustic imitation as a verified reply is not acceptable. Do not infer distress/hunger/meaning from a sound alone.
- Review native dependencies, compiled permission set, third-party notices, signing, safety and a real user/device test before proposing public distribution. Any cloud or upload requires separate explicit consent, cost and privacy review. Recognition remains on-device and the app has no cloud inference or audio upload; version 0.8 adds user-confirmed model downloads.

## Further candidate models and why not integrated

- [ZF-AIM public release](https://zenodo.org/records/23024019): code and weights listed as MIT; release archive is 26.6 GB including data/checkpoints. Its real-time generative model was trained and evaluated for female zebra finch calls in controlled research, not universal reply generation. Portability to TFLite, Android compatibility, individual checkpoint sizes, third-party codec terms and welfare need investigation; no evidence yet that it runs on this phone.
- [Dog2vec paper](https://www.isca-archive.org/interspeech_2025/li25o_interspeech.pdf) and [checkpoint](https://zenodo.org/records/15494042): the 1.1 GB PyTorch checkpoint is an embedding model, not an off-the-shelf reply generator or a standalone calibrated classifier. The retrieved checkpoint page does not specify a licence; do not assume rights. Downstream labelled training, conversion, evaluation and permissions are required.
- [Perch 2.0](https://research.google/blog/how-ai-trained-on-birds-is-surfacing-underwater-mysteries/): embeddings can transfer to other bioacoustic tasks with labelled examples and a downstream classifier; not automatically an animal dialogue model. Hardware/runtime/weights and data licences need evaluation before integration.
- [NatureLM-audio](https://huggingface.co/EarthSpeciesProject/NatureLM-audio): 8B text-generating backbone, non-commercial model, biased towards birds, no validated universal semantics; no animal-audio reply is integrated.

These models address different tasks; stacking all of them does not make an accurate universal interpreter. No animal-like generative reply has been integrated. A pitch-shifted recording would not be ZF-AIM or an AI-generated dialogue, so it is not offered as one.

## Work toward a real response model

- [ZF-AIM paper](https://www.biorxiv.org/content/10.64898/2026.02.12.705387v3): streaming detector → call encoder → event/timing model → zebra-finch neural decoder. It conditions on individual identifiers and interaction history; it is not a general-purpose sound player, universal meaning model, or a crow model. Its results cannot be assumed to apply to another species or uncontrolled phone audio.
- The [public MIT code/weights archive](https://zenodo.org/records/23024019) is 26.6 GB including code, checkpoints and data. `research/inspect_zf_archive.py` is a bounded, read-only ZIP central-directory/README inspection tool: it refuses servers that ignore ranges, limits read size and total bytes, and never executes the archive. The whole archive digest and any checkpoint remain unverified by partial inspection. An isolated research workflow runs its unit tests and attempts the inspection. Successful inventory alone does not prove Android feasibility, licensing for dependencies, correct inference, real-time operation, or welfare.
- [Crow study, Mates et al.](https://pmc.ncbi.nlm.nih.gov/articles/PMC4237024/): some American crow calls were analysed in observed alarm, food recruitment, territorial and other contexts, with a small contextual subset and repeated individuals. This is not a mapping for house crows in India or proof of meaning from a sound. The UI's optional context controls capture only a user's immediate visual observation in RAM; they are not AI predictions, training labels or translated speech and are never saved. They disappear on leaving the result.
- For research prioritisation: extract the published checkpoint names, sizes, architecture/configuration, runtime dependencies and any constraints from the upstream README; reproduce a known inference on a suitably licensed synthetic or publicly permitted input on an isolated machine; then assess export and target-phone memory/latency. Test against held-out species/individuals before generalizing and involve welfare experts before playback. No automatic calls, generated reply or animal behaviour claim is shipped as a result of these investigation steps.

Partial archive investigation completed in CI [run 45030011136](https://github.com/universalrp2003/RP-Android-Apps/actions/runs/45030011136). It read 29,975,698 bytes of metadata/README via HTTP ranges from a 26,633,934,601-byte archive, containing 138,349 entries. The checkpoint subtree contains 24,448 files totaling 15,134,172,060 bytes uncompressed, including multiple versions of training checkpoints. The largest listed checkpoints are approximately 325 MB each. These numbers are archive inventory, not minimum runtime size, tested model memory or a reason to download the full archive; no checkpoint was executed or verified. The app/phone does not include this model.

### ZF-AIM live pipeline investigation

A further [bounded source inspection](https://github.com/universalrp2003/RP-Android-Apps/actions/runs/45033188264) found a Python 3.10/PyTorch 2.1 research stack with audiocraft, recurrent-memory-transformer-pytorch and other dependencies. The documented StreamPlayback setup is for desktop Python/PortAudio, not Android; the paper describes 32 kHz streaming and pre-generated calls rather than on-demand codec decoding. The published pre-generation script invokes GPU cluster jobs. The published README identifies a main interaction model folder `20250417_231457` and call encoder `20250210_171314`; inventory includes a 34,555,252-byte interaction checkpoint and a 150,443,790-byte call-encoder checkpoint, plus detector checkpoints of 156,910,122 and 325,274,695 bytes. These are file sizes, not measured RAM or the minimum required combination; some files contain training state or duplicate versions. The archive also lists a two-bird subset of pregenerated calls, but the files are approximately 2.21 GB and 2.58 GB uncompressed, respectively; a subset by individual is not necessarily small. It is not established that these are adequate or licensed for redistribution independent of the release. No checkpoint has been downloaded, deserialized or executed. In particular, PyTorch/joblib files can execute code while loading and must be handled only in a restricted isolated environment after provenance review. The repository URLs shown in the upstream README returned HTTP 404 during our check, so the archive, not those links, is the accessible source examined here.

The [live configuration inspection](https://github.com/universalrp2003/RP-Android-Apps/actions/runs/45033313926) specifies individual bird IDs, 32 kHz, 0.1-second segments, a CPU detector, an interaction pipeline containing Encodec, summary and interaction checkpoints, and a `PreGenSampler` response stage. The configuration points to an `interaction_pipeline...` checkpoint directory; the earlier separately inventoried checkpoint files must not be assumed interchangeable without verifying configuration and hashes. The size of one response bank is a serious phone-storage obstacle, not proof that a smaller validated bank is impossible. The paper’s performance measurements were for the controlled experimental setup, not this Android prototype.

## Additional routes: pet contexts and broader recognition

- [CatMeows v1.0.2](https://zenodo.org/records/4008297) provides 440 meows from 21 cats in three observed experimental conditions: brushing, unfamiliar isolation and waiting for food. These are experimental labels, not proven intentions, needs, emotions or diagnoses. The Zenodo record specifies research/non-commercial use (CC BY-NC 4.0) and attribution; a paper and third-party repositories contain conflicting CC BY statements, so treat the official record conservatively and obtain clarification before commercial use or model distribution. No recordings are included here. A 21-cat, two-breed corpus cannot establish performance for Tamil Nadu street cats or household recordings. We added a research-only spectral-feature baseline with cat-disjoint cross-validation and a most-frequent-class comparator, not an app feature. It verifies the published archive checksum and does not save models or audio.
- [Dog2vec](https://www.isca-archive.org/interspeech_2025/li25o_interspeech.pdf) gives embeddings and requires a separately trained and validated task head. [EmotionalCanines](https://dl.acm.org/doi/pdf/10.1145/3746027.3758286) labels dog arousal/valence using human annotations on two breeds, with dog-disjoint splits. Such labels do not prove a dog's internal feelings; licence, held-out environments and hardware are unresolved. Neither is a dog-response generator.
- [ECOGEN](https://github.com/ixobert/birds-generation) generates augmented spectrograms from supplied sounds for classifier training, not an interaction-conditioned reply. Code/model licences and checkpoint provenance remain unresolved; no integration.
- [BirdNET+ V3 developer README at 2026-11-13 commit](https://github.com/birdnet-team/birdnet-V3.0-dev/tree/134b602643529036b668a22df0d175f42eeea299) describes 11,709 species, more non-bird taxa, and a 71 MB pruned LiteRT model; its model licence is Apache 2.0 with a separate acceptable-use policy. It is a recognition candidate, not a response model; exact file, checksum, label map, outputs, native ops, acceptable-use terms and local-phone performance need verification. It cannot be dropped in as the legacy BirdNET model. Existing imports remain unchanged.

### First independent cat baseline result (research only)

[Run 45034226482](https://github.com/universalrp2003/RP-Android-Apps/actions/runs/45034226482) successfully checked the official dataset ZIP against the publisher's MD5 and ran five-fold **cat-disjoint** cross-validation on its 440 clips/21 cats. The simple spectral-feature logistic baseline obtained 42.0% clip accuracy, 43.6% balanced accuracy and 41.1% macro F1. A per-fold most-frequent-label baseline obtained 50.2% clip accuracy (the isolation condition has 221/440 clips). Confusion matrix, rows and columns brushing, food, isolation: `[[46,39,42],[27,50,15],[58,74,89]]`. This simple classifier did not beat the majority baseline on overall accuracy and is not suitable for the app. It is not a benchmark of other models, nor evidence of emotion detection or new-cat/phone field performance; clips within each cat are correlated, and estimates from only 21 cats are uncertain. One archive filename contains session 4 despite the record's stated session values 1–3; the parser accepts a single session digit. The ZIP was not committed, no audio or trained model was uploaded, and only aggregate metrics were retained.

## BirdNET+ 3.0: executable feasibility probes

[Host run 45038196978](https://github.com/universalrp2003/RP-Android-Apps/actions/runs/45038196978) fetched the 2026-11-13 Zenodo **3.0** FP16 pruned LiteRT model and labels, verified the publisher's MD5 checksums and computed SHA-256: model `f1fcdefebfba04b34fb9d8856b318c4d924738f2a78087d6d0950cdcce215a88`, labels `88d976477fac81127ac8ac4c215c37749d0a6537944112ea606d321317cb7640`. On synthetic sine/noise in the Linux LiteRT runtime it produced finite 11,725 class scores and 1,280 embeddings; [Android research run 45038420850](https://github.com/universalrp2003/RP-Android-Apps/actions/runs/45038420850) also ran a synthetic sine through this same exact file on an x86_64 API 35 emulator with the app's current TensorFlow Lite dependencies. This does **not** demonstrate target-phone or real-world performance. The file is provided to tests only, not bundled or imported by the app.

The exact label table contains *Corvus splendens* (House Crow), *Bos taurus* (Domestic Cattle), *Felis catus* (Domestic Cat), and *Hemidactylus frenatus* (Asian House Gecko). Exact string searches for *Canis lupus familiaris* and *Rattus rattus* returned no match; that does not establish whether alternative names or related species are present. A label existing does not establish that the model correctly identifies that animal, especially on local recordings. A synthetic 1 kHz tone produced a maximum class score of 0.388; do not treat an arbitrary score threshold as proof that an animal is present.

[Positive-only cat experiment 45038495377](https://github.com/universalrp2003/RP-Android-Apps/actions/runs/45038495377) ran this model on the 440 CatMeows clips (8 kHz source, resampled to 32 kHz, truncated at 3 seconds or right-padded with silence). The Domestic Cat class ranked first in 361/440 clips and in the top five in 415/440; 343/440 had a class score at least 0.35. These are **positive-sample counts, not accuracy**: there are no negative examples, threshold calibration or validation of non-meow detection, and independence from BirdNET training data has not been established. The CatMeows terms are non-commercial research; audio was downloaded into CI temporary storage only, not redistributed. Grouped or external, local, noisy, mixed-animal, negative and real-phone testing remains necessary before deployment. The model identifies possible sound sources, not call meaning or a generated reply.

## Crow-specific generation lead and limits

[CrowGPT pinned source as of 2026-11-15](https://github.com/benfaerber/crowgpt/tree/c0239c688ffb36866b3c3bb741578612a2f3c5f5) reports an approximately 18.7M-parameter autoregressive crow-call generator, alongside separate call-type classifiers. The author says the generator weights and decoder are gated behind a **no-playback agreement**, and explains that BirdNET-based realism scores are circular because BirdNET selected training data. We have not accepted that agreement, downloaded or run the weights, or independently validated the results. The five named classifier heads cover American crow, carrion crow, common raven, rook and hooded crow—not the house crow observed in the user's tree. Its own documentation says no call has yet been translated. CPU/Android feasibility, the generator/codec terms, training-data rights and independent evaluation remain unverified. This is a specific research candidate, not permission to play sounds to crows or evidence that it replies correctly to house crows. Do not integrate or bypass its gating or no-playback conditions.

A [Punjab house-crow acoustic observation study](https://www.biologyjournal.net/archives/2025/vol7issue2/PartB/7-3-7-158.pdf) reports calls during breeding observations, including incubation; it does not provide a tested model for interpreting an arbitrary phone recording. Do not infer that a crow in a tree is nesting, hungry, alarmed or communicating a particular message solely from the call or species ID.

## Online and faint-sound exploration

The user has authorized considering internet use for this app. That does not by itself select a provider, authorize charges, or establish an audio retention policy. The [NatureLM-audio research demo](https://huggingface.co/blog/EarthSpeciesProject/nature-lm-audio-ui-demo) offers an experimental hosted interface for uploaded audio and text questions; it is not validated translation, an animal-audio response generator, or a production API with established availability, pricing or retention guarantees. Model weights are CC BY-NC-SA; other dependencies and hosted service terms must be reviewed separately. We have not uploaded the user's audio or connected the app to that service. Before an optional online mode: identify and verify an actual provider and service terms, obtain explicit informed per-upload consent (recordings may include nearby people), prohibit covert upload, bound data, explain retention/security/cost, handle no network transparently and offer cancellation, then independently test its outputs. Do not queue or store private recordings silently while waiting for internet.

[Behavior-conditioned animal vocalization generation](https://arxiv.org/abs/2610.16382) reports a research generator for six specific species and externally specified textual context, not a universal, self-understanding reply system. Source code, usable weights, service availability, licence, conditional response accuracy and safety require verification. Controlled synthetic generation, even online, must not be presented as validated dialogue or played near wildlife without appropriate welfare review.

For faint recordings the 0.7 prototype optionally listens for nine seconds and evaluates three 3-second windows. It does not increase actual microphone sensitivity or signal-to-noise ratio; selecting the strongest of three uncalibrated outputs increases the opportunity for false positives. No claims of improved accuracy have been made without held-out faint-call and negative/noise recordings. Audio remains on-device/in RAM; version 0.8 adds explicit model downloads, not audio uploads.


Version 0.8 adds user-confirmed HTTPS downloads of the two pinned BirdNET+ 3.0 files from the publisher. It verifies SHA-256, limits size, confines redirects to trusted HTTPS publisher hosts, retains already installed files, and waits for validated connectivity only while foreground. Network state and Internet permissions are present; no audio is sent. Species notes are limited to general observations and must not imply call context, intent or acoustic analysis of the particular recording. House crow note source: [eBird species account](https://ebird.org/species/houcro1/TZ-09).

### Candidate for later call segmentation: BirdCODE (not integrated)
The [BirdCODE preprint](https://www.biorxiv.org/content/10.64898/2026.07.31.742086v1.full) describes species-labelled bird vocalization onset/offset detection across 9,258 species, intended for communication research. Segmentation could eventually help isolate an individual call before a species-specific analysis or reply experiment; it does **not** translate calls or generate responses. Its [inference repository](https://github.com/earthspecies/sound-event-detection) describes a roughly 1.1 GB download and CPU demo taking about 1.5 minutes, and lists MIT for repository code; verify weight and dependency licences separately. No endpoint, mobile conversion, performance on faint house-crow recordings, or safety has been verified. Do not add its large weights to the app or claim it is better on this phone without a reproducible independent benchmark. Compare call-boundary detection and false positives on consented, rights-cleared, held-out local recordings, including quiet calls, speech, traffic and silence. Then investigate a species-specific call-type/context dataset and genuinely conditional generator, with explicit uncertainty and independent behavioural validation before any playback. This is research direction, not a promise of translation or a completion date.

### Species-conditioned audio generation candidate (not a reply)
Reviewed [ar-bird-vocalization](https://github.com/hamuladm/ar-bird-vocalization/tree/86ac8a4a517f057623e838468d7694510a722011) at revision `86ac8a4a517f057623e838468d7694510a722011`: repository declares MIT for code, but the documented inference expects locally trained checkpoints; public trained checkpoint availability and separate dependencies' model/data licences are unverified. The described GPT/SNAC and AudioGen approaches condition generation on species identity, not an observed call, behavioural intent, or the user's words. The author estimates ~4 GB GPU memory for LLaMA inference and ~8 GB for AudioGen. No house-crow support or real-phone feasibility verified, and no code or weights were executed. Its species-like output must not be described as a response or translation. [WhAM](https://arxiv.org/html/2512.02206v1) likewise generates sperm-whale acoustic style from audio prompts, explicitly not semantics, and cautions about playback harms; neither approach justifies playing synthetic signals to animals. Next gate before integration: obtain verifiably usable checkpoints and licences, establish target species and input conditioning, run sandboxed offline synthetic inference and independent listening/negative controls, and assess welfare with appropriate expertise. User text-to-animal-meaning mapping remains an open research problem.

### Geographic model compatibility investigation (not enabled)
The [reference implementation pinned at 134b602](https://github.com/birdnet-team/birdnet-V3.0-dev/blob/134b602643529036b668a22df0d175f42eeea299/birdnet_v3.py) specifies Geomodel V3.0.4 with scientific-name matching, week 1–48 (four per month), an example 0.03 occurrence gate, and retains acoustic labels not covered by the geo model. Its reference uses ONNX; the [publisher's v3.0.4 release](https://github.com/birdnet-team/geomodel/releases/tag/v3.0.4) also lists a 7,705,320-byte FP16 TFLite export with SHA-256 `bee9d29461404c76f812798747288f40d6e0143ce72dd825872a5b8785732e1f` and a separate labels file. The occurrence model is not a certainty of absence, nor is the reference threshold validated for our location or recording conditions. Scientific-name differences, duplicate names, missing taxa, and known taxonomy/range issues such as [the v3.0.4 barn owl issue](https://github.com/birdnet-team/geomodel/issues/35) can wrongly suppress results; keep unmapped taxa and don't silently hide rare species. A bounded CI research script compares the two pinned label files; it does not run inference or filter audio. Before enabling anything, verify hashes/licences/acceptable-use, TFLite input/output/delegate and label ordering on Android, check mapping ambiguity and test measured outcomes with independent rights-cleared positive and negative local audio. Obtain explicit consent for any location use, offer manually selected coarse location and an off switch, and process locally. No location is currently used or requested.

The [label-only CI check](https://github.com/universalrp2003/RP-Android-Apps/actions/runs/45112079114) verified both publisher file SHA-256 values. Exact scientific-name comparison matched 10,874 of 11,725 acoustic rows; 851 did not match (including any blank/environmental labels); none of the 14,082 geomodel rows had duplicate scientific names. Both *Corvus splendens* and *Felis catus* appear once in each list. These counts are not a measure of geographic accuracy, and do not imply every unmatched row is an animal or that a matched species gets the right regional score. No geomodel inference or real-audio experiment was performed.

### Wood Frog in Tamil Nadu: geographic plausibility (0.17)

A phone test produced a Wood Frog (*Lithobates sylvaticus*) guess in Tamil Nadu. The species is native to North America, so this is a plausible geographic false positive: the acoustic model has no location input, its 0.5 score gate is uncalibrated, and a local frog with a similar call is one possible explanation. The app does **not** suppress the guess. It shows a per-result bilingual caveat that the species is native to North America and that a similar-sounding local frog or a model error is possible, alongside the existing statement that no location filter is used. No location permission is requested and no region model is enabled.

The geomodel label-comparison work above is not a validated region filter for this use. Enabling one would require explicit consent for any location use, a tested occurrence model, correct scientific-name mapping, measured false-positive and false-negative results on rights-cleared local audio, and an off switch. Rare or out-of-range species must not be silently hidden. A Wood Frog result in Tamil Nadu is therefore displayed as an uncertain guess with a geographic caveat, not as evidence that the species is present.

#### Taxon group badge (0.18)

The publisher documents the label CSV columns as `birdnet_id`, `scientific_name`, `common_name`, `taxon_group` (`Aves`, `Insecta`, `Amphibia`, `Mammalia`, `Actinopterygii`, `Reptilia`, `Arachnida`, `Anthropogenic`, `Geophony`, `Music`), `inat_id`, `ebird_code` and `common_name_<lang>` for 36 languages ([BirdNET+ V3.0 README, pinned commit 134b602](https://github.com/birdnet-team/birdnet-V3.0-dev/blob/134b602643529036b668a22df0d175f42eeea299/README.md#labels)). The app reads `taxon_group` as an optional column and shows it as a small per-result badge only. It is not used to filter, reorder or suppress anything, and an unmapped or missing value shows no badge. The CI research probe checks the downloaded file for `Amphibia` on *Lithobates sylvaticus* and `Aves` on *Corvus splendens*. The localized `common_name_<lang>` columns have not been checked for Tamil coverage and are not used yet.

#### APK size (0.19)

The 0.18 release APK was 461 MB although bundled assets total 4.3 MB (`yamnet.tflite` 4.1 MB, licence texts). The `tensorflow-lite-select-tf-ops:2.14.0` dependency, added in commit `da75c65` because the BirdNET-Lite V2.4 model contains Flex ops, ships a roughly 100 MB `libtensorflowlite_select_tf_ops.so` per ABI, uncompressed in a universal APK for arm64-v8a, armeabi-v7a, x86 and x86_64. The BirdNET+ V3 model does not need it: the publisher's [`examples/tflite_minimal.py`](https://github.com/birdnet-team/birdnet-V3.0-dev/blob/134b602643529036b668a22df0d175f42eeea299/examples/tflite_minimal.py) and our `research/probe_birdnet_v3.py` both run it with `ai_edge_litert` and no Flex delegate, and the V2.4 model was already retired from the UI in 0.12. YAMNet uses the built-in TFLite audio kernels. 0.19 drops the dependency and the legacy inference code; the workflow now reports APK size, largest entries and per-ABI native totals and fails above 150 MB. Per-ABI split APKs remain an option if a future dependency needs native code again.
